# 9단계: 스토리 설계 (복수 서사 · 챕터 구성)

## 목표

이미 구현된 4개 퀘스트 체인(채집 → 사냥 → 강화 → 보스)에 **"보스 나바쉬가 내 마을을 불태웠고, 나는 복수한다"** 라는 서사를 얹는다. 게임플레이 구조는 그대로 두고, **왜 그 일을 하는지**를 대사·연출·UI로 채운다.

이 문서는 **설계 문서**다. 코드 변경 없음. 실제 대사는 10단계, 시스템 구현은 11단계, 위젯 제작은 12단계 문서에서 다룬다.

## 선행 단계

5단계(퀘스트 체인), 8단계(보스전 & 엔딩)까지 완료된 상태를 전제한다. 스토리는 기존 퀘스트 체인 위에 얹히므로 체인 순서가 바뀌면 챕터 순서도 함께 바뀐다.

## 읽어야 할 파일

`Docs/README.md`(퀘스트 체인 4종), `Docs/05_quest_expansion.md`(체인 동작 방식), `Docs/08_boss_ending.md`(보스/엔딩 흐름). 코드는 이 단계에서 읽을 필요 없음.

## 설계

### 1. 로그라인

> 잿불의 나바쉬가 루엔 마을을 태운 밤, 견습 수비대원 **그레이**는 스승의 부러진 검을 쥔 채 살아남았다.
> 남은 사람들을 먹이고, 앞잡이를 베고, 부러진 검을 다시 벼린 뒤 — 재가 내리는 성문 너머로 걸어 들어간다.

### 2. 등장인물

| 코드 | 이름 | 역할 | 대응 액터 (기존 구현) |
|---|---|---|---|
| `Grey` | 그레이 | 플레이어. 루엔 수비대 견습. 말수가 적고 감정을 잘 드러내지 않는다 | `APy_Grey` |
| `Haran` | 하란 | 촌장. 살아남은 사람들을 붙들고 있는 노인. 퀘스트 4종을 순서대로 발주 | 기존 `ANPC_Quest` (`BP_UI_NPC_Quest`를 쓰던 그 NPC) |
| `Godon` | 고든 | 대장장이. 스승 발렌의 검을 알아본다 | 기존 `ANPC_Enhance` |
| `Mira` | 미라 | 행상인. 마을이 불탄 뒤에도 장사를 접지 않은 현실주의자 | 기존 `ANPC_Shop` |
| `Narbash` | 나바쉬 | 보스. "잿불의 나바쉬". 태운 것의 이름을 세지 않는다 | `AMon_Narbash` (`bIsBoss = true`) |
| — | 발렌 | 그레이의 스승, 전 수비대장. **습격 때 사망 — 등장하지 않고 대사로만 언급** | 없음 (에셋 불필요) |

> **새 NPC는 만들지 않는다.** 세 NPC 모두 이미 배치돼 있는 액터에 대사만 붙인다. 신규 캐릭터 에셋/애니메이션 작업이 0이 되도록 인물을 설계했다.

### 3. 챕터 구성 — 기존 퀘스트 체인에 1:1 매핑

| 챕터 | 제목 | 게임플레이 (기존) | 스토리 트리거 | 신규 필요물 |
|---|---|---|---|---|
| 프롤로그 | 잿더미의 아침 | 없음 (조작 가능한 채로 나레이션) | 마을 레벨 최초 진입 시 1회 | 나레이션 4줄, 폐허 드레싱 |
| 1장 | 살아남은 사람들 | 약초 5 채집 (Gather) | 하란 1번 퀘스트 대화 | 대사, 챕터 타이틀 카드 |
| 2장 | 놈들의 앞잡이 | 고블린 5 처치 (Kill) | 하란 2번 퀘스트 대화 | 대사, 챕터 타이틀 카드 |
| 3장 | 부러진 검 | 무기 강화 1회 (Enhance) | 하란 3번 + 고든 대화 | 대사, 챕터 타이틀 카드 |
| 4장 | 잿불의 성문 | 보스 맵 이동 → 나바쉬 처치 (Kill) | 하란 4번 + 보스 아레나 진입 | 대사, 보스 조우/페이즈2/사망 대사 |
| 에필로그 | 재가 되어도 | 없음 | 보스 사망 후 | 나레이션 3줄 + 엔딩 화면 문구 |

### 4. 스토리 진행 흐름

```
Lv_Village 최초 진입
   └─ [StoryTrigger: LevelStart] 프롤로그 나레이션 4줄
         └─ 하란에게 말 걸기
               ├─ 1장 인트로 대사 → 챕터 카드 "제 1장 · 살아남은 사람들" → 기존 퀘스트 수락창
               ├─ (진행 중 재대화) 진행 중 대사 1줄 → 창 안 열림 (기존 동작 유지)
               └─ (완료 후 재대화) 완료 대사 → 다음 챕터 인트로 → 챕터 카드 → 수락창
                     ⋮  (2장 · 3장 동일 패턴, 3장은 고든에게도 전용 대사)
                     └─ 4장 수락 후에만 보스 포탈 통과 (기존 RequiredQuestID 게이트)
                           └─ Lv_Boss 진입
                                 ├─ [StoryTrigger: Overlap] 보스 조우 대사 4줄
                                 ├─ HP 50% → 페이즈2 전환 시 나바쉬 1줄
                                 └─ 사망 → 나바쉬 유언 1줄
                                       └─ 3초 후 에필로그 나레이션 3줄 → 엔딩 화면
```

### 5. 기존 시스템에 붙는 지점 (신규 코드 최소화 원칙)

| 스토리 요소 | 붙는 곳 | 방식 |
|---|---|---|
| 프롤로그 나레이션 | 레벨에 배치한 `AStoryTrigger` | 신규 액터 1개 (11단계) |
| 퀘스트별 인트로/진행/완료 대사 | `FQuestData`에 대사 ID 배열 3개 추가 | 기존 `ANPC_Quest::Interact_Implementation` 흐름에 삽입 |
| 챕터 타이틀 카드 | 퀘스트 수락 대화 직전 | `FQuestData`의 챕터 라벨/제목 필드 |
| 보스 조우 대사 | 보스 아레나 입구 `AStoryTrigger` | 코드 변경 없음 (트리거 배치만) |
| 페이즈2 / 사망 대사 | `AMon_Narbash::EnterPhase2` / 사망 분기 | 대사 ID 배열 2개 추가 |
| 에필로그 | `APy_Grey::ShowEnding` 앞 | 대사 재생 후 기존 엔딩 위젯 표시 |
| 1회성 보장(재진입 시 재생 안 됨) | `UStoryStateSubsystem` | `UGameInstanceSubsystem` 1개 (11단계) |

### 6. 만들지 않는 것 (범위 고정)

과설계를 막기 위해 **아래는 이번 스토리 작업에 포함하지 않는다.** 필요해지면 별도 단계로 뺀다.

- 레벨 시퀀서 기반 시네마틱 컷씬 (카메라 연출은 대사창 + 챕터 카드로 대체)
- 대사 선택지 / 분기 서사 (선형 1갈래)
- 음성(보이스) 및 립싱크
- 세이브/로드 (스토리 진행은 게임 인스턴스 수명 동안만 유지 — 게임을 껐다 켜면 처음부터. 캡스톤 시연 기준으로 충분)
- 다국어 로컬라이제이션 테이블 (한국어 고정, `FText`로만 담아둠)
- 습격 당일을 플레이하는 튜토리얼 스테이지 (프롤로그는 나레이션으로 처리)

### 7. 후속 문서 순서

```
9. 스토리 설계 (이 문서)
   └─→ 10. 대본 (모든 대사 확정 — 데이터 입력용 표)
         └─→ 11. 대사/연출 시스템 구현 (C++)
               └─→ 12. 스토리 UI 제작 명세 (WBP — 사용자 에디터 작업)
```

10단계는 글쓰기만, 11단계는 코드만, 12단계는 에디터 작업만 다룬다. 11단계 코드는 10단계의 대사 ID 명명 규칙에 의존하므로 **순서를 지킬 것.**

## 에디터 작업 (사용자)

이 단계에서는 아래 "분위기 작업"만 진행해도 된다 (코드 대기 불필요, 11~12단계와 병행 가능).

1. **마을 폐허 드레싱** — `Lv_Village`를 습격 이후 상태로 바꾼다: 무너진 벽/그을린 목재 배치, 잔불 파티클(기존 나이아가라 재활용), 안개(Exponential Height Fog) 농도 ↑, 디렉셔널 라이트 색온도를 잿빛으로. **레벨을 새로 파지 말고 기존 `Lv_Village`를 그대로 고치는 것을 권장** — 포탈/NPC/스폰포인트 배치를 다시 할 필요가 없다.
2. **보스 아레나 톤 맞추기** — `Lv_Boss`에 재가 내리는 파티클(눈 파티클 색상만 회색으로), 붉은 림 라이트.
3. **초상화 텍스처(선택)** — 대사창 좌측에 띄울 인물 초상화 4종(그레이/하란/고든/나바쉬). 없으면 12단계 명세대로 `PortraitImage`를 비워두면 자동으로 숨겨진다 — **필수 아님.**

## 완료 기준

이 단계는 문서 단계이므로 PIE 테스트가 없다. 아래를 확인하면 완료.

- [ ] 챕터 6개(프롤로그~에필로그)가 기존 퀘스트 체인 4개와 어긋나지 않는다.
- [ ] 등장인물 5명이 전부 **기존 액터**에 매핑되어 신규 캐릭터 에셋 요구가 없다.
- [ ] "만들지 않는 것" 목록에 팀이 동의했다 (이 목록이 곧 11~12단계의 작업량 상한선이다).
