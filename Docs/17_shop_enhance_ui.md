# 17. 상점 / 강화 창 개편

> 상점(`UUI_Shop`)과 강화 창(`UUI_Enhance`)을 인벤토리(`I`)/장비창(`U`)과 같은 **골드 이중 테두리 판**으로 다시 만들고, 쓰기 편하게 조작을 손봤다.
> 위젯 블루프린트(`.uasset`)는 건드리지 않았다. 창의 위젯 트리는 C++가 `NativeOnInitialized`에서 통째로 조립하고, `bUseCodeBuiltLayout`(기본 켜짐)을 끄면 예전처럼 WBP 레이아웃을 쓴다.
> (WBP_Shop / WBP_ShopSlot / WBP_Enhance의 디자이너 화면에는 예전 레이아웃이 그대로 보인다 — 게임에서 뜨는 것은 코드로 조립한 새 창이다.)

## 1. 한눈에 보기

### 상점

| 항목 | 내용 |
|------|------|
| 구조 | 위쪽 `[구매] [판매]` 탭 + `수량 [×1] [×10] [최대]` 칩 → 한 줄 목록(스크롤) → 안내/결과 메시지 → 소지품 수 / 소지금 |
| 거래 | **줄 아무 데나 클릭**하면 선택한 수량만큼 바로 거래 (구매/판매 버튼을 따로 누를 필요 없음) |
| 수량 | `×1`, `×10`, `최대`(살 때는 골드·인벤토리 자리가 허락하는 만큼, 팔 때는 가진 만큼 전부). 골드가 모자라도 살 수 있는 만큼은 산다 (×10인데 4개 값밖에 없으면 4개) |
| 한 줄 | 아이콘(종류별 테두리 색) · 이름 · 종류/효과 · 값(총액) · 보유 수 · `구매 ×N`/`판매 ×N` 표시. 못 사는 이유가 있으면 붉은 글씨(`골드 부족`, `가방 가득`)로 바뀐다 |
| 결과 | 창 아래 한 줄 메시지: `체력 포션 ×3 구매   -150 G` (초록) / `골드가 부족합니다.` (붉은색). 3초 뒤 서서히 사라지고 안내 문구로 돌아간다 |
| 빈 목록 | 판매 탭이 비었으면 "팔 수 있는 아이템이 없습니다" 안내 |
| 닫기 | `Esc`, 창 오른쪽 위 `X`, NPC 앞에서 `E`를 한 번 더 |

이전에는 소지품이 가득 차 있어도 골드만 빠지고 아이템이 사라질 수 있었는데, 이제 자리를 먼저 확인한다 (`UInventoryComponent::GetAddableCount`).

### 강화

| 항목 | 내용 |
|------|------|
| 위쪽 | 지금 든 무기 아이콘/이름, 큰 `+N` 단계 표시와 `→ +N+1`, 단계 마름모(`MaxWeaponLevel`개, 지난 단계는 금색) |
| 공격력 | `공격력  35  →  45   (+10)` — 강화하면 얼마가 되는지 미리 보인다 |
| 필요한 것 | 재료(아이콘·이름·`보유 / 필요`)와 골드(`보유 / 필요`). 충분하면 초록, 모자라면 붉은색 |
| 버튼 | 큰 `강 화 하 기`. 못 할 때는 이유가 글자로 나온다: `재료가 부족합니다` / `골드가 부족합니다` / `최대 강화 완료` |
| 결과 | 성공하면 아이콘 테두리가 흰빛으로 반짝이고 `강화 성공!   +3   공격력 +10` 메시지 |
| 조작 | `Enter` 강화, `Esc`/`X`/NPC 앞에서 `E` 닫기 |

## 2. 코드 구성

```
Source/Capstone/
  UI_PanelParts.h        (신규) 상점/강화 창이 같이 쓰는 부품: 창 틀+제목줄(BuildFrame), 소지금 배지, 글자 버튼/탭 스타일,
                         아이콘 칸(FIconBox), 아이템 종류별 색/종류 글자/요약 (PanelUI::)
  UI_Shop.h/.cpp         UUI_Shop: 탭·수량·목록·메시지·거래 로직 (거래는 줄이 아니라 이 창이 처리)
  UI_ShopSlot.h/.cpp     UUI_ShopSlot: 목록의 한 줄 (줄 전체가 버튼, 눌리면 OnTradeRequested 방송)
  UI_Enhance.h/.cpp      UUI_Enhance: 강화 창 본체
  NPC_Shop.cpp / NPC_Enhance.cpp   창 열기/닫기 (아래 "입력 모드")
  InventoryComponent.*   GetAddableCount(ItemID) 추가 (CanAddItem이 이것을 쓴다)
  Py_Grey.*              SetNPCPanelOpen(bool) 추가
  UI_InventorySlot.cpp   종류별 테두리 색을 UI_PanelParts.h 것으로 교체 (동작 변화 없음)
```

- 색/브러시/텍스트 헬퍼는 기존 `UI_QuestStyle.h`(`QuestUI::`)를 그대로 쓴다. 팔레트가 같아서 인벤토리/장비창/퀘스트창과 한 벌로 보인다.
- 기존 `BindWidgetOptional` 이름(`GoldText`, `CloseButton`, `BuyItemsPanel`/`SellItemsPanel`, `WeaponLevelText` 등)은 그대로라서 WBP를 계속 쓰던 방식(`bUseCodeBuiltLayout` 끔)도 동작한다.
- `ShopWidgetClass`/`EnhanceWidgetClass`/`ShopSlotClass`가 비어 있어도 코드 조립 창이 뜬다 (예전에는 BP에 클래스를 안 넣어 두면 아무 일도 안 일어났다).

## 3. 입력 모드 (NPC 창이 열려 있는 동안)

두 NPC가 창을 열 때마다 입력 잠금/마우스 커서/입력 모드를 따로 만지던 코드를 `APy_Grey::SetNPCPanelOpen(bool)` 하나로 모았다. 이 값도 `RefreshPanelInputMode`의 "열린 창이 있는가" 판정에 들어가므로,

- 상점을 연 채 `I`/`U`로 인벤토리·장비창을 열었다 닫아도 **입력 잠금과 마우스 커서가 풀리지 않는다** (이전에는 풀려서 상점을 마우스로 쓸 수 없게 됐다).
- 인벤토리를 상점 옆에 함께 띄워 놓고 볼 수 있다 (상점은 화면 가운데, 인벤토리는 오른쪽, 장비창은 왼쪽).
- 상점을 닫을 때 인벤토리가 아직 열려 있으면 커서를 유지한다.

`Esc`가 먹으려면 위젯이 키보드 포커스를 가져야 해서 창은 `SetIsFocusable(true)`이다. 입력 모드를 바꾸는 순간 포커스가 게임 뷰포트로 넘어가 버리므로, 창이 뜬 직후 몇 틱 동안(`FocusTriesLeft`) `NativeTick`에서 포커스를 다시 가져온다 (NPC가 연 실제 경로에서 `Esc`/`E` 닫기를 확인했다). NPC 앞에서 `E`를 다시 누르면 `Interact`가 다시 불리므로 그때 `CloseShop/CloseEnhance`를 호출한다.

## 4. 에디터 작업 (사용자)

없음. 기존 `BP_NPC_Shop`/`BP_NPC_Enhance`와 `WBP_Shop`/`WBP_ShopSlot`/`WBP_Enhance`를 그대로 두면 된다 (WBP가 코드 조립 트리로 대체되어 뜬다).
새 상점 NPC를 배치할 때 `ShopItemIDs`(예: `HpPotion`)만 넣으면 된다.

## 5. 완료 기준 (PIE 테스트)

- [ ] 상점 NPC 앞에서 `E` → 창이 화면 가운데에 뜨고 마우스로 조작된다. `Esc` / `X` / `E` 어느 쪽으로든 닫히고 닫으면 이동·공격이 돌아온다.
- [ ] 구매 탭에서 줄을 클릭 → 골드가 줄고 인벤토리에 늘고, 아래에 초록 결과 메시지가 뜬다. `×10`/`최대`로 여러 개가 한 번에 거래된다.
- [ ] 골드가 모자라면 값과 표시가 붉게 바뀌고 클릭해도 거래되지 않는다. 소지품 20칸이 가득 차면 `가방 가득`으로 바뀐다.
- [ ] 판매 탭에서 전리품을 팔면 골드가 늘고, 다 팔면 줄이 사라진다. 목록을 스크롤한 상태에서 거래해도 스크롤 위치가 튀지 않는다.
- [ ] 상점을 연 채 `I`를 눌러 인벤토리를 열었다 닫아도 마우스 커서가 남아 있고 상점이 계속 조작된다.
- [ ] 강화 창에서 재료 3개 + 골드가 있으면 `강화하기`가 켜지고, 누르면 `+N`이 오르고 공격력이 `AttackPerEnhance`만큼 오르며 아이콘이 반짝인다.
- [ ] 재료/골드가 모자라면 버튼이 비활성화되고 이유가 글자로 나온다. `MaxWeaponLevel`에 닿으면 `최대 강화 완료`.
